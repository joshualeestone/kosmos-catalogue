# publish: sign the catalogue and publish it to GitHub Pages (kosmos#4632)

Part 2 of moving the Kosmos roles/teams catalogue into this repo. Part 1 (5ca2c54, on main) exported
the sources losslessly from kosmos tools/catalogue at 53c496952: building here gives the same 69 roles
and 21 teams, field for field, as kosmos engine/catalogue-roles.js and catalogue-teams.js (checked with
a deepStrictEqual and a one-character control that differed).

## Calls
- Hosting: GitHub Pages from this repo, reached at installkosmos.com/catalogue/ through a Vercel
  rewrite in chaoskosmos-site (a separate PR). Rejected: R2 (needs a new bucket-scoped key minted by
  the Cloudflare account owner); raw.githubusercontent (rate-limited, not our address).
- Integrity: Ed25519 signature over the exact bytes of catalogue.json. Private key only in the
  CATALOGUE_SIGNING_KEY secret of the github-pages environment, deployable from main only (no other copy kept: losing it means a new pair and a Kosmos
  release); public key committed as signing-key.pub.pem and carried by Kosmos. Rejected: a pinned
  hash in the app, which would tie every catalogue edit to a Kosmos release.
- sign.js verifies against the committed public key before writing, so a wrong secret fails the
  publish rather than shipping a file every Kosmos refuses.
- License MIT, the same as Kosmos, where this content already shipped publicly.

## Steps
1. [x] build.js copies the portraits the catalogue names into dist/.
2. [x] sign.js + tests (tamper, wrong key, bad signature, committed key type).
3. [x] .github/workflows/publish.yml: test, build, sign, deploy-pages on push to main.
4. [x] Pages enabled with build_type workflow.

Weakest premise: that a Vercel external rewrite to github.io serves these files unchanged. The
signature makes a changed file fail closed (Kosmos keeps its built-in roles), not open.

## Review iteration 1 (changes)
- Actions pinned to commit SHAs; the key moved to an environment secret (github-pages, main only),
  with a NEW key pair because a secret cannot be read back to move it; repo-level secret deleted.
- `serial` (commit time) inside the signed bytes, against replay of an old catalogue.
- `avatar.imageSha256` for each portrait; a portrait that is a link is refused.
- kosmos-builtin-roles.json: member roles must exist here or in Kosmos; catalogue keys may not
  reuse a built-in key (both checks were Kosmos tests that do not run on a catalogue-only change).
- The .sha256 file is gone: the signature replaces it.

## Review iteration 2 (changes)
- The serial (commit time) is refused when it is over an hour ahead of the clock.
- Role keys, team keys and slots are validated in the builder before they name a file; portrait
  ids must be unique; malformed groups.json or team members are reported, not thrown.
- main() takes a root and output folder, and is tested end to end in a git copy.
- Deferred: branch protection or CODEOWNERS on main. Merge access to main is the trust root, as it
  is for Kosmos itself, whose code reaches every install the same way; Josh's standing rule for this
  beta is that ready PRs merge without waiting on a reviewer. Stated in the README.
- For Kosmos (next PR): a minimum serial carried in the app, so a copy holding no catalogue yet
  refuses one older than its release.
