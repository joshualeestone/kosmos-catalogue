# kosmos#5021 step 2 (the data half): a menu group on every team

Josh's live test (#5021): group Create a Team's "Choose a team" menu like the role picker. Mona builds the board half
(engine/catalogue.js accepting `group`, optional and plain text when present, and the menu reading it, falling back
to the kind). This is the data, split with her 08:00 2026-10-02.

## What this does
- `team-groups.json` (new source, read by lib/source.js with the same not-a-link rule as groups.json): the headings in
  order for each kind, Mona's ten from #5021 verbatim (Business: Marketing and sales, Customers, Money, Strategy and
  research, Operations and people, Technology; Personal: Home and family, Money and paperwork, Health, learning and
  work, Plans and projects).
- `group` on all 77 teams (one line each after `kind`; each file otherwise byte-identical), mapped from #5021's lists
  by label (77 matched, none left over, every group within one kind).
- build.js: each team's group must be one of its kind's; every heading must have a team (no empty heading); the
  names get the same text guards; the published catalogue carries `group` on each team and `teamGroups` (the order).
- tools/import-packet.js: a replaced team keeps its group (as its rank); a new team has none and the build names it.

  only the team fields it knows and ignores any other key, and ignores unknown top-level keys, so installed boards
  read this catalogue exactly as before. Weakest premise: that no served build has a stricter check; every served
  build since #4632 ignores unknown keys (review 1 measured all four downloading versions of engine/catalogue.js:
  the current two accept this catalogue; the two oldest refuse today's main build too, for team size, unrelated).

  null, a list, an object, missing); a heading itself must have no outer or doubled spaces.
